# 桌面 UI 设计

版本：0.3；日期：2026-10-06；状态：初审发现已修复，子代理复审中，用户未审核。前序产品审核见 `reviews/01-product-review.md`。

## 1. 审核材料与边界

交互稿：`design/desktop-preview.html`。预览控制条可以切换 macOS / Windows、宣纸 / 玄墨及具体页面；控制条位于 App 外，只用于审核。示例作品、模型、路径和请求结果都是演示数据。该稿不读取磁盘、不保存 Key、不连接真实模型，也不证明原生窗口行为已经通过。

预览自身检查记录见 `design/preview-verification.md` 与 `design/evidence/preview-checks.json`，129 项通过（修订稿），仍不计作桌面 App 验收。

最终 App 复用原 React 工作台组件；设计稿仅说明桌面差异的布局、视觉、入口和状态，不替代原工作台的全部 29 类面板实现。原组件的功能与产品能力矩阵共同约束后续实现。

## 2. 与 Web 保持一致的部分

- 三栏结构为左导航 / 中对话 / 右内容，左栏默认 260px。首次启动与未打开内容时右栏隐藏；打开内容后依原逻辑均分侧栏外空间。保留显隐、全屏、拖拽与标签记忆。
- 原侧栏品牌、创建作品/对话、作品阁、树节点、会话入口与底部设置入口不移动。账号区域改为本地作者与本地数据状态，不显示邮箱/平台套餐。
- 对话保留标题、模型在 composer 的选择位置、消息/候选卡、问答/选稿占槽与实体 chip；顶栏不恢复已移除的会话下拉/作品 pill/上下文指标。
- 内容区保留原 Tab、MarkdownEditor 的预览/编辑/分屏、版本回执与原评论方式。预览默认、长文本纸纹不变。
- `design/assets/web-tokens.css` 直接复制来源 `globals.css` 的字族、主题、圆角/阴影与对话令牌；SVG 是现有温玉资产。来源见 `assets-provenance.json`。此预览使用本地 Noto Sans SC / 系统宋体，最终包内补齐基线字族和原组件样式。
- 仅宣纸和玄墨；系统跟随开关只决定选择哪套主题。正文纸纹，玄墨导航/设置界面墨石纹理。

允许差异区域：36px 桌面标题带、侧栏本地作者信息、作品本地路径操作、向导底部目录行与离线创建按钮、新应用设置/迁移/恢复界面。不得以这些新增点重画原有创作 UI。

## 4. 窗口带

高度 36px。标题在平台安全区内居中，长标题单行省略并提供完整标题提示；安全区在所有宽度生效。内容简洁为「玄香印 · 当前作品」或「玄香印 · 设置」。主体分栏从其下开始，所有原 UI 几何不因平台控件改变。

macOS：左 80px 控件安全区，系统红/黄/绿交通灯。Windows：右侧依原生 overlay 留位，约 138px 起；最小化、最大化/恢复、关闭。示意控件在交互稿禁用；实现使用系统控件，不能用 HTML 仿制。

标题带空白为拖拽区，按钮/菜单/输入框非拖拽区。双击按系统窗口行为处理；关闭前保存，失败有恢复/取消路径。全屏、不同缩放/DPI、窗口失焦时对系统按钮的变化必须在目标系统验收。

## 5. 作品目录行与创建流程

在向导底部模板摘要与动作之前增加「作品目录」行：目录输入展示（只读）+「选择目录」按钮；辅助文案「正文、设定、会话与附件保存在此目录」。建议目录以占位形式显示，不能当成用户已授权。

未指定：两种创建动作禁用，行内提示「请选择本地作品目录」。取消系统对话框保持当前状态；校验中有加载状态；只读/非空冲突/已绑定目录错误紧邻路径，操作仍不可用。有效时路径尾部显示「可用」。每次进入新建流程都重新获得目录确认，取消或成功创建不会把旧授权带入下一部作品。挂起授权仅属于当前未发送的建书草稿。长路径单行截断，并可展开/复制完整路径；中文和空格正常。

「放入对话草稿」保持现有确定语义，只挂起目录与拼贴草稿，不调用模型/写作品；草稿状态明确「待创建」，首条发送再获得本地建书回执。「创建并手动写作」立即建空作品并打开无章节的概览，显示作品路径与本地状态，不发 AI 请求；向导模板脑洞保留在对话输入草稿，作者可继续编辑。取消保留原工作台状态。

聊天取消后保留脑洞、清除目录授权，再次发送重新询问目录；创建新对话不复用其他挂起草稿的授权。已绑定目录行内报错，第二部作品不得重复创建在同一目录。

聊天 `startNovelFromChat` 的未授权状态使用同一目录行，确认前不建书；此处说明书名来自已有草稿，仅确认保存位置。

## 6. 设置容器与表单

从原侧栏齿轮打开应用内设置面板，居中最大约 960 × 680px，左右留白至少 24px；不足时填可用区域、内容独立滚动。分类宽 172px，右侧表单最大阅读宽 640px。顶部标题/关闭，底部始终可见保存回执与「取消 / 保存设置」。窄窗口压缩边距并将分类导航转为横排，避免遮挡控件。

表单用原 Input、Select、Switch、Button、Dialog 的视觉和状态。label 与字段垂直间距 6px，字段组 18px，章节间 24px；核心字号 13–14px，说明 12px；图标 15–16px。错误用 `destructive`，成功用 `success`。Key 字段不回填明文，清除为独立按钮。

通用页的数据根路径为只读展示 +「迁移」；默认作品父目录不等于新作品授权。模型页首次启动为空列表；添加后编辑名称、协议、端点、ID、用途、能力、上下文/输出与思考档位。列表可选择多个模型，停用、缺少 Key 的配置明确标记不可用。保存不自动联网；测试前确认端点/模型/短文本与供应商费用，测试中可取消。界面页实时预览但未保存有脏标记；取消恢复原主题/字级、行距及进入前的分栏布局，不重挂载或清空创作草稿。快捷键只在 App 聚焦时生效，空录制、系统保留键、已绑定其他命令的重复键在录制框内阻止确认。有效录制立即在目标命令行显示；保存后保留，取消恢复进入前的绑定。外部审核条可显示已有配置冲突的禁止保存态。

切换分组或关闭且有修改：居中小确认框「设置尚未保存」，操作「继续编辑 / 放弃修改 / 保存并继续」。保存失败保留输入及脏标记，确认框不直接关闭。主对话框和子对话框分层时，焦点移到当前最高层；下层设置/向导与工作台 inert，Tab / Shift+Tab 在最高层循环，关闭后恢复原焦点。已有作品正文不受设置保存影响。

## 7. 迁移、故障与恢复

- 迁移确认分别显示原根、当前权威根与用户显式选择的新根，目标校验前禁止提交；失败后可重选并重新校验。窗口控件、Escape、页面切换和返回共用迁移关闭保护。提交时即更新权威根，两平台通用页同步显示。确认同时显示数据大小、可用空间、作品目录保持原位，以及成功后旧根仅本应用数据的清理范围。恢复快照放新根，未知文件与作品目录不清理。
- 进度阶段为保存草稿、复制、校验、提交、清理；提交前可取消，提交后只显示状态和完成动作。部分失败明确指出当前权威根；新根已启用但旧副本未清理时不能用简单成功图标掩盖。
- 根失联提供「重新定位 / 从备份恢复」，显示失联的权威路径，不悄悄启用旧根。备份列表区分应用数据恢复快照与作品备份，校验失败禁止恢复；有效根快照需另选恢复目录并明确确认。作品失联提供「重新关联目录」。保留原路径和草稿，不呈现虚构空作品。
- 重启恢复显示草稿/保存时间、关联作品及「查看并恢复」；恢复先比较版本，选择恢复后出现可编辑、明确未提交的恢复稿，继续编辑后比较内容同步更新，当前已保存版本保持可见。关闭保存失败提供「重试 / 导出草稿 / 取消关闭」，不能用关闭按钮直接丢稿；关闭框的 X / Escape 均按取消关闭处理，应用与草稿仍打开。
- 模型测试 401/限流/超时等在结果区脱敏显示；撤销模型使新请求停止并保留已生成候选，清除 Key、删除及停用使用各自确认动作并立即撤销授权，不依赖设置表单保存；随后的「取消设置」不能复活撤销状态。新增/普通编辑仍按保存与取消语义处理。

## 8. 审核与后续一致性

交互稿可预览两平台×两主题、四设置分组、作品目录有效/冲突、快捷键冲突、未保存设置、迁移成功/失败/待清理、恢复。设计稿行为验证只验证该稿，不是最终测试用例文档或桌面 App 测试。

子代理审核要求：产品范围与设计状态一致、原UI入口/令牌/SVG保持、窗控安全区/长路径/滚动/窄窗可用、错误和数据丢失路径完整、设计和真实原生行为界限明确。修复后记录复审结论。

用户审核重点：窗口带与两系统按钮位置；工作台保持 Web 布局；四类设置容器/导航；创建目录行与两个动作；迁移/恢复流程。用户明确批准前，技术方案、测试用例、App 实现与桌面验收仍未开始。

## 9. 修订与复核

初审 UI-01–UI-10 的修复对应：目录授权逐次取得；模型撤销不随取消恢复；迁移全关闭路径守卫；Windows 权威根与目标选择；布局取消回滚；快捷键录制反馈与冲突；640px 导航与 1024px 超长标题；根失联、备份校验和保存失败退路；空列表到多模型及思考档位；空作品概览与恢复编辑草稿。独立结论见 `reviews/02-ui-review.md`。
